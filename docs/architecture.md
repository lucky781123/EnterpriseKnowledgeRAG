# 系统架构、数据流与边界

## 1. 目标闭环

```text
上传 API / Git 同步
  → 文件验证
  → 解析、清洗、结构化切块
  → Embedding + BM25F 索引构建
  → 完整性检查与版本发布
  → OIDC 身份、租户与 ACL
  → Dense/BM25F 双路召回
  → RRF + Reranker
  → Parent 回溯与证据组装
  → Linear 问答 / 有界 Agentic
  → SSE、引用、审计、指标
```

## 2. 数据权威性

1. PostgreSQL 是文档版本、ACL、任务状态和发布状态的权威来源。
2. 对象存储保存原文及解析产物，必须可按 `source_id + version_id + content_hash` 定位。
3. Weaviate 中的检索对象是可重建派生数据，不是权限唯一权威。
4. Redis 中的数据可丢失并回源；缓存键必须关联租户、权限范围版本、索引版本、模型和 Prompt 版本。
5. Checkpoint 不使外部 LLM、索引写入和状态保存形成跨系统原子事务；依靠幂等、重放和副作用记录。

## 3. 文档发布语义

文档新版本先解析、切块、Embedding、写索引并完成完整性检查，再由 PostgreSQL 发布为可见版本。未发布产物不得作为有效证据。删除或撤权先撤销业务可见性，再异步清理索引、缓存、引用和原文派生物。

查询必须固定本次回答使用的文档版本，不跨版本拼接冲突证据。Parent 回溯、引用详情和 Checkpoint 恢复都要重新执行授权和版本检查。

## 4. 权限闭环

- Keycloak/OIDC：身份、签名、issuer、audience、过期校验。
- 应用：当前租户成员关系、RBAC、文档 ACL、版本可见性。
- 检索前：两条召回通道使用一致租户和 ACL 条件。
- 检索后：Parent 回溯、Reranker 输入、上下文、引用、缓存命中再次复核。
- 权限撤销：约定在途请求语义；后续检查点阻断，无法承诺已发送内容可撤回。

## 5. 在线与后台资源隔离

- `interactive`：用户查询、首 token 敏感，优先级高。
- `background`：评测、回归、摘要，必须有界并发，可暂停。
- `ingestion`：只使用 Embedding/Reranker，不占用最终回答模型队列。

应用层使用有界 `asyncio.Semaphore`/队列、总 deadline、取消和迟到结果丢弃。模型服务的真实并发能力由运行时和硬件决定，必须通过基准而非线程数推断。

## 6. 非目标

- 首期不承诺复杂扫描 PDF、复杂表格和版面完全还原。
- 不承诺单机 Minikube 等价于生产高可用或独立故障域。
- 不把本地模型压测外推为云供应商容量。
- 不实现开放式多 Agent、复杂工具调用、在线学习或语义答案缓存作为首期前置条件。
